# 自动发布策略

## 适用条件

仅在用户明确要求“不需要人工审核、直接发布”时启用。状态文件设置：

```json
{
  "publish_policy": "autonomous",
  "auto_publish": {
    "eligible": true,
    "reason": "双源确认、允许题材、原始素材可用"
  }
}
```

## 自动发布门

必须全部满足：

- 事件进入微博、抖音、今日头条、B站等至少两个公开热榜，或一个热榜加一个可信媒体源。
- 核心事实至少有两个独立来源，时间、主体、冲突点一致。
- 找到原始曝光视频、原始帖子或原始截图，而不是只有二次转述。
- 事件发生在 `0–24 小时` 内，或存在新的权威进展。
- 能生成 mixed-original-carousel 五图：封面、完整说明、三张跨来源事件图。
- 图片、标题、标签、音乐已自动校验。
- 账号登录有效，无验证码、二次验证或安全拦截。
- 同一事件 24 小时内未发布过。

## 自动跳过的高风险类别

自动发布模式不等待人工审核，因此以下内容直接跳过，不建草稿、不发布、不询问：

- 灾害、事故、伤亡、失踪、遗体和救援现场。
- 未成年人受害、校园暴力、儿童隐私或未成年人身份信息。
- 性侵、性骚扰受害者身份、私人病历和精神健康隐私。
- 身份证、住址、电话、单位、聊天记录、家庭关系等隐私泄露。
- 未经权威确认的刑事指控、犯罪嫌疑、企业违法定性。
- 血腥、裸体、色情、猎奇或令人强烈不适的画面。
- 医疗诊断、药品建议、金融荐股、投资承诺。
- 地域攻击、性别仇恨、民族宗教冲突和群体煽动。

高风险事件可以进入监控记录，但 `auto_publish.eligible=false`，不进入自动发布队列。

## 自动执行

满足自动发布门的题目：

1. 自动确定 `content.angle`。
2. 自动生成五图 mixed-original-carousel。
3. 标题使用短事件名，正文只放标签，不写长文案。
4. 按事件风格选择纯音乐。
5. 直接上传并发布，不等待用户确认。
6. 发布后刷新作品管理，记录标题、时间、张数和状态。
7. 使用 `claude-to-im` 推送发布结果和作品链接/标题。

## 自动失败处理

- 登录失效或出现验证码：停止并通知用户处理。
- 原始来源不可达或无法确认：跳过，不发布。
- 图片生成失败：跳过并记录错误。
- 平台审核拒绝：保留错误信息，停止重试，避免同一内容反复提交。
- 网络或浏览器异常：记录失败；下一次巡检重新评估，不重启已提交任务。

## 防重复

状态文件保存 `event_fingerprint`、`source_urls`、`published_at` 和 `publish_status`。同一事件、同一原始来源和同一核心句在 24 小时内不得重复发布。

## 通知原则

- 没有合格新热点：保持安静，不通知。
- 成功发布：发送一条简短发布确认。
- 登录、验证码、平台拒绝或关键异常：立即通知。
- 高风险类别直接跳过，不做无关提醒。
## 运行架构

- 热点巡检必须使用独立 cron/local 任务，不要把 heartbeat 绑定到很长的聊天线程。
- heartbeat 会继承线程历史；历史过大时，请求 JSON 可能达到数 MB，导致工具调用字段被截断或代理报错。
- cron 任务只读取小型 `AUTOMATION.md`、策略文件和状态文件，不读取聊天历史。
- 状态文件只保留最近事件、去重指纹、发布记录和错误，定期裁剪，避免无限增长。
- 单个巡检周期的提示词保持精简，完整流程放在工作区文档中。
## CC Switch 工具调用兼容性

如果自动任务报错：

`Failed to deserialize the JSON body into the target type: input: missing field 'call_id'`

按以下顺序处理：

1. 确认任务没有绑定超长聊天线程；改为独立 cron/local 任务。
2. 不要在长线程上使用 heartbeat，否则请求会携带完整历史并持续膨胀。
3. 不要生成大段工具脚本；拆成小步读取、检查和执行。
4. 将模型从 `deepseek-flash + high` 切换为 `deepseek-v4-flash + max`。
5. 更新后保留 `failed_runs_only`，避免每次巡检都打扰用户。
6. 下一次运行仍失败时，暂停自动化并检查 CC Switch 的 Responses API 工具调用序列化，不要盲目重试。
